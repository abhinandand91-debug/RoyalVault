# Unity Lifecycle, Serialization and Assets

## Lifecycle

- `Awake`: cache own components and set up internal state.
- `OnEnable` / `OnDisable`: subscribe and unsubscribe enable-scoped events; stop enable-scoped tweens and coroutines.
- `OnDestroy`: release what lives as long as the object (event subscriptions on longer-lived objects, owned tweens).
- Do not rely on script execution order; make ordering explicit in `GameBootstrap`.

## References

- Validate required Inspector references once, with a clear error message.
- Use `TryGetComponent` where a component may legitimately be missing.
- No `SendMessage` or string-based dispatch.

## Serialization

- Renaming or retyping a serialized field breaks existing prefabs and assets; use `[FormerlySerializedAs]` when a rename is needed.
- Never hand-edit GUIDs; keep `.meta` files with their assets.
- Before moving, renaming or deleting an asset, search the scenes, prefab, assets and code (the builder loads art by path) for references.
- The prefab and scenes are generated by **Royal Vault > Build Everything**: change the builder, not the generated files.

## Licensed content

- Licensed art, audio and packs stay in their git-ignored folders: `Assets/RoyalVault/Art.Private`, `Assets/Hovl Studio`, `Assets/RSG_Crowns_of_Kemet`.
- Packages whose licence forbids redistributing source (PrimeTween) are installed from a registry, never copied into `Assets`.
